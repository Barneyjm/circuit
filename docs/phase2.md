# Phase 2: calibration without training

2026-09-18. Reference eval set: `data/eval.jsonl`, 2,199 items, 22
families (17 training-eligible, 5 held out), 1,000 Choice / 799 Noul /
400 Score. Each item has a state generated by Gemini 3.5 Flash from a
family brief, and a reference distribution = average of Jev
(`jev-latest`) and Gemini 3.5 Flash asked for calibrated probabilities.
The two teachers agree on the argmax 87.9% of the time; the averaged
reference has mean normalized entropy 0.31, i.e. the teachers are
usually confident.

No human-labeled subset yet (handoff budgets one; not done tonight).

Metrics are all against the averaged reference: `acc` = model argmax
equals reference argmax; `ECE` uses that as the label; `KL` =
KL(ref‖model); `sel@90` = accuracy on the 90% most confident items;
`agree Jev` = argmax agreement with Jev alone.

## Methods, 8B base, applied cumulatively where noted

Temperature is fitted per type by grid search on half the items (by
id hash), minimizing KL to the reference; every row below with a `T=`
reports on the *other* half. Rows without `T=` report on all items.

### all types

|---|---|---|---|---|---|---|

| + temperature (noul 1.5, choice 0.9, score 2.0) | 0.723 | 0.056 | 0.406 | 0.231 | 0.753 | 0.727 |

## Read

- **Temperature is the only post-hoc method that pays.** It halves Score
  ECE and improves KL and Brier across the board. The fitted values say
  something about the base model: it is over-confident on yes/no (T > 1
  softens), slightly under-confident on multi-way choice (T < 1), and
  badly over-confident on ordinal scores (T = 2).
- **The ECE/KL tension is real.** Fitting T to KL raises Noul ECE from
  0.029 to 0.060 because the reference itself is soft on ambiguous
  items; matching that softness looks like "under-confidence" when ECE
  uses the reference *argmax* as a hard label. Both numbers are
  reported; which one a gate should trust depends on whether the
  downstream consumer wants agreement with the teacher's decision or
  the teacher's uncertainty. The handoff's headline is ECE; for
  distillation KL is the honest target.
- **Permutation averaging and debiasing don't help here.** On the small
  public tasks they moved order-flip rates; on this set, where options
  carry descriptive text and the reference is soft, they cost a point of
  accuracy and buy nothing in calibration. Dropped from the default
  configuration.
- **Score questions are the weak type.** 52% argmax agreement, KL 0.68
  raw. Ordinal levels rendered as A/B/C/D lose their order to a base
  model; the trained head in Phase 3 can learn it.
- **Worst families** (raw 8B, argmax agreement): frustration_level 0.43,
  deadline_realistic 0.44 (held out), scheduling_conflict 0.50 (held
  out), code_has_bug 0.57, email_folder 0.58, pr_risk 0.58. Two of these
  need arithmetic or interval logic (deadline, scheduling), which
  single-token scoring on a base model will not do well regardless of
  calibration.

## Decision

Post-hoc alone reaches the Phase 2 exit bar on ECE (< 0.10) for every
type after temperature, but argmax agreement with the reference is 72%
overall and 52% on Score, which is not "within 10 points of the
frontier references." Phase 3 is required. Training data (5,100 items,
17 families) is ready; the trainer, head, and LoRA scorer are smoke
tested end to end.

|---|---|---|---|---|
| all | 0.720 → 0.731 | 0.039 → 0.033 | 0.432 → 0.366 | 0.750 |
| Noul | 0.766 → 0.780 | 0.029 → 0.032 | 0.286 → 0.225 | 0.786 |
| Choice | 0.765 → 0.778 | 0.085 → 0.052 | 0.449 → 0.392 | 0.806 |
| Score | 0.517 → 0.517 | 0.141 → 0.139 | 0.682 → 0.580 | 0.537 |

Scale buys a point of agreement and a real KL improvement on Noul and
Choice, and nothing at all on Score argmax. Ordinal questions are a
representation problem, not a capacity problem, at least between 8B
and 14B. That is the single strongest argument for the trained head.
